# ETNIKA — обязательные правила дизайн-системы

Статус: технический контроль текущего редизайна, 05.11.2026. Этот документ не заменяет согласование дизайна.

## Типографика (уже существующая стилистика)

- Заголовки разделов: **Forum**, нормальный вес 400.
- Основной текст, метки и интерфейс: **Geologica**.
- Общий размер крупных заголовков: `--etnika-section-title: clamp(62px,6.25vw,118px)`; для мобильных до 700px — общая переменная `clamp(48px,14vw,72px)`. Изменения этой шкалы делаются централизованно, не в каждом блоке.
- Минимальный размер обычного текста и интерактивных элементов: 16px, токен `--etnika-text-size`. Технические исключения допускаются только после отдельного согласования.
- Нельзя применять `transform:scaleX(...)` к заголовкам для подгонки по ширине: это искажает шрифтовую гарнитуру. Заголовок переносится на узком экране.

- Надписи в верхних линиях секций («ЭТНИКА / пространство студии / всё необходимое уже внутри») — **отдельный типографический стиль**, который уже использовался на сайте: `--etnika-overline-size: clamp(9px,.62vw,11px)` на десктопе, `8px` на мобильном, вес 200, межбуквенный интервал `.13em`. Это исключение для декоративных служебных меток, а не размер основного текста. Применять одинаково ко всем секциям; не подменять размером 16px из основного текста.

## Общая навигация (запрос владельца 05.11.2026)

> «Добавь ещё на сайт меню, как на текущем сайте примерно. Чтобы смотреть было удобнее. Только на первом экране вместо лого ЭТНИКА можно просто оставить Студия автопортрета, а потом когда первый экран прокрутили вниз лого с HERO перемещается в хедер сайта.»

- Хедер фиксирован. На первом экране отображается «Студия автопортрета», при прокрутке HERO логотип «ЭТНИКА» переносится в хедер, на остальных секциях остаётся в хедере.
- Навигация не заменяет ни содержание, ни фотографии HERO и не создаёт отдельного второго меню.
- Внутренние пункты используют существующие `id` разделов. Ссылки на «Открыть студию» и «Блог» открывают реально существующие страницы основного сайта.
- На узких экранах — управляемое кнопкой меню, закрывающееся после выбора ссылки или по Escape.
- Комментарий владельца 06.11.2026: «сами пункты меню как будто слишком кучно друг к другу». Для горизонтальных пунктов на десктопе введён `--etnika-menu-item-gap:clamp(26px,2.2vw,38px)` (примерно 34px при ширине 1536px); на ширине до 1340px — адаптивный `clamp(18px,1.65vw,24px)`. Размер шрифта 16px, расстояния до телефона, мессенджеров и кнопки записи не изменяются. Проверять, чтобы никакие элементы шапки не пересекались.

- Механизм перехода логотипа должен учитывать `prefers-reduced-motion`, переходы и прилипание к шапке проверяются в Chromium.



## Вертикальная компоновка

- Для фотораздела «Пространство ЭТНИКА» высота секции — `calc(100svh - var(--etnika-nav-height))`: она находится целиком **ниже** фиксированной шапки. Внутри контейнера одинаковые верхнее и нижнее поля — `padding: var(--etnika-photo-section-y) 0`. Глобальный `scroll-padding-top` и переход через меню должны выравнивать верх секции точно по нижней границе шапки. **Критерий:** измеренное расстояние от нижнего края шапки до верхней служебной строки совпадает с расстоянием от нижнего края переключателей до низа окна (допуск 2 px). Исправление по прямому замечанию владельца 06.11.2026 «поле сверху и снизу неодинаковое сейчас». Не распространять автоматически на другие секции.
- Вертикальные поля — общий `--etnika-section-y`: 64px (десктоп), 56px (планшет), 44px (мобильный). Если экран физически не вмещает читаемый контент, нельзя скрывать текст ради формального `100svh`; требуется отдельное адаптивное решение.
- Для **фотогалереи пространства** — отдельный общий токен класса фотоориентированных секций `--etnika-photo-section-y: clamp(26px,3.8svh,42px)`. Причина: владелец потребовал максимально использовать высоту фотографиями, но с равными верхним и нижним полями. Это не разрешение менять типографику остальных блоков.
- Галерея / видео / фотоконтент получает **всё оставшееся пространство**, через `minmax(0,1fr)`, а не фиксированные 500–700px.
- Для содержимого grid/flex, способного сжиматься, задаётся `min-height:0`, но без обрезания важных текстов.
- **Обязательное обнуление унаследованного отступа секции:** для фотораздела `#etnika-space-photo { padding:0!important; }`. Исторический слой `etnika-v15-final-layout-fixes` устанавливает `padding-top` и `padding-bottom` по 72px на самой секции с `!important`. Даже при правильной высоте `100svh` это отнимает ~144px у галереи. Автотест должен проверять именно `getComputedStyle(section).paddingTop/Bottom`, а не только текст правил.
- Граница фото и скругления: ровные прямые углы; оригинальные фотографии нельзя заменять или масштабировать без согласования. В кадрах используется `object-fit:cover`, с проверкой положения главного объекта.

## Блок «Пространство ЭТНИКА»

- Без вступительного абзаца о «просторном зале».
- Сохранены: титул, три фотографии (одна большая, две малые), пять категорий, счётчик и подписи при взаимодействии.
- Новое прямое замечание владельца 06.11.2026: «буквы снизу проф свет и пр. слишкмо крупные. Должно быт более аккуратно» — навигационные подписи галереи имеют отдельный мелкий стиль `clamp(12px,.8vw,14px)` на десктопе и 13px в мобильной горизонтальной прокрутке. Это согласованное исключение из общего минимального кегля для интерактивных компонентов.
- Новое прямое замечание владельца 06.11.2026: «при наведении на мелкие фото какие-то розовые рамки образуются» — декоративный розовый `::before` у маленьких фотографий отключён. На клавиатуре допускается только нейтральное выделение фокуса.
- `site/index.html` (рабочая страница) и `site/review-2026-11.html` (предпросмотр) содержат **одинаковую реализацию этого блока**.
- Минимум пять размеров для визуальной проверки: 1920×1080, 1662×896, 1366×768, 390×844, 375×667. Для новых адаптивных изменений проверять также высоту 600px.

## Контроль изменений

**Технические меры, предлагаемые ассистентом, а не дополнительные задачи из переписки:**

1. Автоматическая структурная проверка двух HTML-страниц: отсутствие удалённого текста, сохранность всех фото/переключателей и дизайн-токенов, идентичность блока между рабочей и тестовой страницами.
2. Автоматическая проверка геометрии в Chromium с несколькими размерами окна, включая отсутствие выхода содержимого за нижнюю границу секции. Скриншоты сохраняются как артефакты проверки.
3. После изменения любого CSS перед пометкой «Готово» обязательна проверка визуального результата реальной страницы на десктопе и мобильном, включая шрифты, состояние загрузки фото, вкладки и подписи. Исходный код без визуальной проверки не является доказательством исправления.
4. Не добавлять новый слой поздних `!important`-переопределений вместо изменения общих правил без аудита конфликтов. Исключения локализовать, документировать и проверять.
